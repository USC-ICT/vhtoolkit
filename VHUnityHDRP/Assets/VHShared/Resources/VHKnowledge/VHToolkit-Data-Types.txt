Data types in the Virtual Human Toolkit

Character data in the VHToolkit splits between two kinds of Unity project. The dedicated asset projects, one per rendering pipeline, hold the source art: character meshes and textures exported from Maya or Character Creator as FBX files, plus body animations and facial animations. From those projects the art is built into asset bundles that the end-user facing projects download at runtime.

The application projects hold the per-character runtime data. Authored speech lives in timeline folders per character: the speech audio as OGG files, either recorded or synthesized; transcripts as text files, collected in a master lines sheet; lipsync schedules generated by FaceFX; and nonverbal behavior schedules as XML following the Behavior Markup Language (BML), generated by the nonverbal behavior generator. Unity Timeline files sequence this content into scripted moments, and interface art lives with the shared UI assets.

Configuration is a JSON file named ride.json, defined by the RIDE configuration system and stored in the user's local application data folder rather than in the project, which is how API keys stay out of source control. The debug menu's Config section opens its location.

For live conversation none of the authored speech data is needed: audio, lipsync, and behavior schedules are generated on the fly by the speech synthesis and behavior systems. The authored files exist for scripted content, where a human refines timing and delivery by hand.
